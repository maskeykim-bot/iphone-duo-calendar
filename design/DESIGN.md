# Duo — ひらく、毎日。

紙の手帳の静けさと、必要な予定にすぐ届く操作感。生成物は画面設計と単体 HTML のレビュー用モックであり、アプリ本体・ビルド・保存機構は含まない。

## 寸法・ブレークポイント

[Apple 技術仕様](https://www.apple.com/iphone-duo/specs/)で提示寸法を確認。DPR の確定情報は得られていないため **device pixel ratio = 3** と仮定する。CSS px = 物理解像度 ÷ DPR。ppi は物理密度であり DPR の代用にしない。

| 状態 | 縦向き CSS px（幅 × 高さ） | 横向き CSS px |
| --- | --- | --- |
| 閉じた／アウター | 1398/3 × 2034/3 = **466 × 678** | **678 × 466** |
| 開いた／インナー | 1878/3 × 2670/3 = **626 × 890** | **890 × 626** |
| ハーフフォールド／全体 | **626 × 890** | **890 × 626** |
| ハーフフォールド／片側の仮想領域 | **626 × 445** | **890 × 313** |

ハーフフォールドは画面ピクセル数を半減する状態ではない。中央を水平に折り、上下に等分できる姿勢を設計上の仮定とする。折り目の除外幅は未確定で、モックでは全体内に24pxの保護帯を確保するため上下の実コンテンツ高は等分値より小さい。実機の折り方向・ブラウザの領域報告に応じて調整する。

「同じ縦横比」という依頼の前提に対し、数値の幅/高さはアウター約0.6873、インナー約0.7034で約2.3%差がある。寸法の計算は解像度を優先し、比率を強制して歪めない。

- 幅600 CSS px 未満、または高さ600 CSS px 未満：1列。閉じた初期ホームは、月タブを選択状態にしたまま、日付ヒーロー・次の予定・今日の残り予定・追加だけを表示する。月グリッドと選択日一覧は配置しない。日／週／月タブを押すとホームを終了し、ヒーローと残り予定を隠して、実高さを持つ独立スクロール領域で選んだビューを表示する。日付見出しは1回だけ表示し、閉じた閲覧画面には選択日サイドを置かない。「今日に戻る」でホームに戻る。閉じた縦466×678では次の予定と残り予定のスクロール領域、追加操作が初期表示に収まる。残り予定が増えた場合はリスト内をスクロールする。
- 幅600 CSS px 以上 **かつ高さ600 CSS px 以上**：開いた縦の月は全幅カレンダー＋下部アジェンダ、週は日別の縦リスト。開いた横は後述の見開き配置。日表示は1列。幅のみでは判定しない。閉じた横678×466は1列のコンパクト表示とし、日付と次の予定を同じ段に置き、その直後の残り予定と追加を優先する。月全体の表示は要求しない。
- ハーフフォールド：手動「卓上」指定で上下構成。幅から折り姿勢を推測しない。上にカレンダー、下に選択日の予定と追加ボタン。保護帯24pxの中心を端末高の約50%に固定し、ヘッダー分を上ペイン高から差し引く。上側は手帳の月行を44pxに圧縮する。予定名月行は88pxで2段の帯を維持し、必要時に独立スクロール。保護帯のラベルは負マージンを使わず、帯内に左右12pxの余白を確保して中央揃えで全文を表示する。下側の予定一覧も独立スクロールし、最下部の追加領域とは分離する。回転時も保護帯は上下中央を維持する。
- モックはコンテナクエリを用い、466 / 626 / 890pxのプレビュー幅と縦横回転を用意。狭いレビュー画面では実幅に縮め、寸法ラベルに実幅も記載。端末枠は上記高さを維持し、内容は内部スクロール。
- 計算値は画面全体の理論値。Safariツールバー、safe area、表示ズーム、ソフトウェアキーボードで実際の可視領域は変わる。製品では viewport-fit=cover と safe-area-inset を使い、実機採寸で確定。

## 開いた横向き（見開き手帳）

対象は890×626 CSS pxのインナー画面。物理的な垂直の折り目は **x=445**。左右24pxの外余白、各399pxのページ、中央40px（x=425〜465）の無描画ガターを確保する。枠線の1pxを含むモックでは約1pxの差がある。保護帯にはヘッダーの文字、カード、横罫も通さない。紙色、Duo.、落ち着いた緑、4カテゴリ、日本語UI、本文16pxを維持する。

ヘッダーは44px高の1行。左ページ側にロゴと日／週／月、右ページ側に年月・月送り・今日に戻る・44px角の＋を置く。＋のアクセシブルな名前は「予定を追加」を維持。全幅の追加バーとフッターは置かず、本文まで12pxを空ける。編集シートも右ページ内に収める。

月表示の左ページは「手帳／予定名」を切り替える月カレンダー。予定名は88pxの週行、週あたり2本の複数日帯、3本目以降の +N と継続矢印を維持する。11月の5週を表示でき、6週月などは左ページだけをスクロールする。右ページは選択日の日付・件数と時系列リスト。各予定は76px高＋上余白8px、時刻とカテゴリ／タイトルの2行。5件で420px、見出しを加えても本文領域約540px内に収まり、5件目までスクロールなしで読める。場所は編集シートで確認する。

週表示は日曜始まりの7日間を、左ページに日〜水の4日、右ページに木〜土の3日と「今週の余白」で配置する。各日はページ幅を使う縦リスト。時刻＋本文16pxの予定名を並べ、長い名称は自然に折り返し、「プロジェ…」のような1行省略を強制しない。日付から日表示、予定から編集へ進める。予定が増えた週は本文内スクロール。日表示は左に時系列一覧、右に日付・件数の余白ページを置く。

2026-11-12のサンプルは10:00仕事、12:30プライベート、16:00ゴルフ、18:00仕事、22:30経済指標の5件。閉じたホームは次の予定1件と残り4件を既存のリスト内スクロールで扱う。

見開き専用クラスは開いた横（実幅800px以上・高さ600〜699px）だけに適用する。閉じた縦横、閉じた日／月、開いた縦、ハーフフォールドは既存の配置に戻す。フォーム入力や選択状態は回転で保持し、アプリ本体・ビルド・永続化は変更しない。

## スワイプ

全レイアウト共通で、現在のビューの **左スワイプ＝次、右スワイプ＝前**。日は1日、週は7日、月は1か月だけ送る。月末は移動先月の末日に丸め、週・日は相対日を維持する。期間見出しと選択日・アジェンダを同時に更新し、選択日をライブ通知する。既存の ‹ › は残す。閉じたホームでは月を送り、ホームを終了して月表示へ進む。

受け付けるのはカレンダー本文（日セル・予定を含む）、アジェンダ、閉じたホームの予定面。開いた横は左右どちらのページも同じ期間を1回送る。ガター／折り目保護帯、ヘッダー（月送り・表示タブを含む）、追加ボタン、編集・削除ダイアログ、入力欄では受けない。ダイアログが開いている間は全面で無効。端末端20pxから始まる操作はOSの戻る操作を優先して除外する。

1本指の開始点から終了点で判定。水平距離 |dx| ≥ 50px **かつ** |dx| / max(|dy|,1) ≥ 1.5 を満たした指離しだけで確定する。高速フリックの特例は設けない。開始後12pxで縦優勢（|dy| ≥ |dx|）なら、その操作は最後まで縦スクロールとして扱う。水平優勢でも比率不足なら未確定のまま、期間は変更しない。スクロールを開始済みなら途中から水平へ乗り換えない。Web実装は対象に touch-action: pan-y pinch-zoom を指定し、pointercancel は必ず中止。2本指・ピンチも中止する。

移動8px以下だけをタップ候補とし、それを超えるドラッグではセル選択・予定編集を発火しない。確定スワイプに伴う click を抑止し、1操作1期間、慣性による連続送りなし。横ドラッグ中に本文を追従させず、確定後200msで遷移。旧内容は指の方向へ32pxずらして消え、新内容は反対側32pxから定位置へフェードイン（ease-out）。ヘッダーと追加ボタンは固定、描画は各ペイン内にクリップしガターへ侵入させない。遷移中は次の送りを受けない。prefers-reduced-motion: reduce では移動・フェードなしで即時切替。

発見性は初回閲覧時だけ、月送りの下に「左右にスワイプで日・週・月を移動」を12pxの補助色で4秒表示。領域を予約せず、操作対象には重ねない。以後は不要。モックでは端末外の常設説明図で方向のみを示し、スワイプ実装と初回ヒントは含めない。

## 開いた縦：月（626×890）

左右分割を廃止し、上に全幅の月、下に選択日のアジェンダ。外余白16px、本文幅594px（枠線込みのモック実幅592px）、日セル約84px。従来の約50px幅から拡大し、予定名を12pxで約6文字まで読める。本文とアジェンダのタイトルは16pxを維持し、月内の密な短冊のみ12pxの補助表現。長い名称は月内では末尾省略、選択日アジェンダでは全文を折り返す。読みやすさの優先順位は、月の予定名、選択日の全文、装飾の順。

上部ブランド36px、期間タブ52px（44px＋上下4px）。月ペインは **482px固定**：年月・‹ › 44px、曜日26px、6週×64px＝384px、凡例28px。曜日下の余白は0。5週月でも月ペイン高を保ちアジェンダ位置を動かさない。月全体の6週をスクロールせず表示する。「手帳／予定名」は開いた縦で非表示、常に予定名。目的に合わない点だけの表示へ戻らないため。別の姿勢で選んだ手帳／予定名の状態は保存し、回転時に復元する。

週行64pxは日付20px、予定2レーン×18px、残件数8px（罫線は内側）。単日短冊と複数日帯で **共通の2レーン** を使い、4段には増やさない。複数日を先に、開始日時順に配置し、同一週内で占有する全日が空いているレーンへ割り当てる。単日は残ったレーンに時刻順で配置。複数日は週境界で分割し ←／→ で継続を示す。収まらない分は各日ごとの「+N」（複数日も件数に含む）。日付選択で下部に全件を表示、短冊・帯のタップで編集へ。タイトルに時刻は詰め込まずアジェンダに時刻・カテゴリを併記する。

月とアジェンダの間は8px。アジェンダは残り領域（626×890で226px（枠線込み））、上罫線と上余白8px、日付・件数見出し36px、カード最小54px＋下間隔6px。サンプルの先頭3件はスクロールなし。長いタイトルは自然に高さを増やし、増えた分・4件目以降は見出し下の **リストだけ** をスクロール。任意長タイトルまで常に3件を保証するものではない。月とリストを重ねず、全画面スクロールは使わない。

下部は上余白8px＋44px高の「＋ 予定を追加」を右寄せ（左右20pxの内余白）。全幅バーと飾りのフッターを外し、52pxに収める。表示領域がsafe area等で減った場合は、まずアジェンダを3件分確保し、月ペインを独立スクロールへ切り替える。週行や本文を縮小しない。モックの縦専用条件は幅600–799px・高さ800px以上かつ通常の開いた状態。閉じた／卓上は除外し、890×626の見開き規則には影響させない。

## 開いた縦：週

7列を廃止し、日曜から土曜まで1日1ブロックの縦リスト。月ペインと同じ全幅594px、下部アジェンダは置かない。年月見出し44pxを除いた本文を独立スクロール。日ブロックは内余白上下8px・左右12px、間隔8px。左100pxに日付（タップで日表示）、間12px、右約458pxに予定。予定は最小44px、内余白8px、時刻46px＋間12px＋全文タイトル16px／行高24px。長文は省略せず自然に折り返し、ブロックの高さを増やす。空の日も日付と「予定なし」を表示。終日・複数日予定は各該当日に載せ、時刻欄を「終日」とし、タップで期間を確認できる。週全体を画面内に圧縮せず、可読性を優先する。追加ボタンは月と同じ下部右寄せ。

## v1 と後続の境界

v1は日／週／月、2つの月表現、4カテゴリ、追加・変更・削除、幅への追従、ローカル保存。製品化時の保存はIndexedDBを第一候補とし、この成果物では接続しない。クラウド送信、アカウント、同期、サービスワーカー、インストール処理は対象外。Safariの「共有 → ホーム画面に追加」で使う想定の画面設計のみ。

## レビュー手順

mockup.htmlを直接開き、十分な幅のブラウザで次を確認する。狭いブラウザでは実幅表示を確認し、基準寸法の確認時はブラウザを広げる。

1. 閉じた縦466×678の初期画面で今日・次の予定・残り4件のスクロール領域・追加のみが表示され、月グリッドや選択日一覧が出ないことを確認。閉じた横678×466でも1列で同じ操作が使えること。
2. 閉じた／開いたの縦横で日・週・月を切替。本文を末尾までスクロールし、追加がカードやグリッドを覆わないこと。日・週で手帳／予定名が消え、開いた縦以外の月で復帰すること。
3. 開いた縦626×890の月で、予定名が初期表示され、選択日を変えても行高が変わらず前後月を含む全日が表示されること。2026年8月などの6行月でもアジェンダ3件分の高さが残ること（空の日は空状態）。開いた縦の週が日別縦リスト、開いた横は左4日／右3日＋余白、閉じた縦横の週が縦並びであること。
4. ハーフフォールドの縦横で中央24pxの保護帯、上の月と下の予定を確認。各ペインの末尾までスクロールし、追加操作と重ならないこと。
