# Duo — ひらく、毎日。

紙の手帳の静けさと、必要な予定にすぐ届く操作感。生成物は画面設計と単体 HTML のレビュー用モックであり、アプリ本体・ビルド・保存機構は含まない。

## 寸法・ブレークポイント

[Apple 技術仕様](https://www.apple.com/iphone-duo/specs/)で提示寸法を確認。DPR の確定情報は得られていないため **device pixel ratio = 3** と仮定する。CSS px = 物理解像度 ÷ DPR。ppi は物理密度であり DPR の代用にしない。

| 状態 | 縦向き CSS px（幅 × 高さ） | 横向き CSS px |
| --- | --- | --- |
| 閉じた／アウター | 1398/3 × 2034/3 = **466 × 678** | **678 × 466** |
| 開いた／インナー | 1878/3 × 2670/3 = **626 × 890** | **890 × 626** |
| ハーフフォールド／全体 | **626 × 890** | **890 × 626** |
| ハーフフォールド／片側の仮想領域 | **626 × 445** | **890 × 313** |

ハーフフォールドは画面ピクセル数を半減する状態ではない。中央を水平に折り、上下に等分できる姿勢を設計上の仮定とする。折り目の除外幅は未確定で、モックでは全体内に24pxの保護帯を確保するため上下の実コンテンツ高は等分値より小さい。実機の折り方向・ブラウザの領域報告に応じて調整する。

「同じ縦横比」という依頼の前提に対し、数値の幅/高さはアウター約0.6873、インナー約0.7034で約2.3%差がある。寸法の計算は解像度を優先し、比率を強制して歪めない。

- 幅600 CSS px 未満、または高さ600 CSS px 未満：1列。今日・次の予定・今日の残り予定を先頭に置き、月や選択日の詳細はその下の独立スクロール領域に置く。閉じた縦466×678では当日の3予定と追加操作が初期表示に収まる。残り予定が増えた場合はリスト内をスクロールする。
- 幅600 CSS px 以上 **かつ高さ600 CSS px 以上**：月＋選択日を2列、週は7列（1日1列）。日表示は1列。幅のみでは判定しない。閉じた横678×466は1列のコンパクト表示とし、日付と次の予定を同じ段に置き、その直後の残り予定と追加を優先する。月全体の表示は要求しない。
- ハーフフォールド：手動「卓上」指定で上下構成。幅から折り姿勢を推測しない。上にカレンダー、下に選択日の予定と追加ボタン。保護帯24pxの中心を端末高の約50%に固定し、ヘッダー分を上ペイン高から差し引く。上側は月の行を44px（予定名48px・タイトル1件と帯を縮小）に圧縮して主要部分を見せ、必要時に独立スクロール。下側の予定一覧も独立スクロールし、最下部の追加領域とは分離する。回転時も保護帯は上下中央を維持する。
- モックはコンテナクエリを用い、466 / 626 / 890pxのプレビュー幅と縦横回転を用意。狭いレビュー画面では実幅に縮め、寸法ラベルに実幅も記載。端末枠は上記高さを維持し、内容は内部スクロール。
- 計算値は画面全体の理論値。Safariツールバー、safe area、表示ズーム、ソフトウェアキーボードで実際の可視領域は変わる。製品では viewport-fit=cover と safe-area-inset を使い、実機採寸で確定。

## 画面一覧とレイアウト

| 画面 | 内容 |
| --- | --- |
| 今日／閉じたホーム | 大きい日付、次の予定の時刻・名称・カテゴリ、続く予定、下部の追加。月・週・日へ移動可能 |
| 月・手帳 | 月間の小さなカテゴリ印と選択日の詳細を並置。日セル選択で右側更新 |
| 月・予定名 | 日セルに色付きの予定名。複数日予定は週グリッドを横断する帯。週境界で分割し継続矢印を付ける |
| 週 | 選択日を含む日曜始まり7日間の予定概要。狭幅では縦並び。日別の追加・詳細へ |
| 日 | 選択日の時系列リスト。終日を先頭に置く。空の日には追加導線 |
| 予定シート | 追加／編集、タイトル、カテゴリ、開始・終了、終日、場所。編集時に削除確認を開く |
| ハーフフォールド | 上に閲覧、折り目保護帯、下に選択日の確認と追加。入力はシートで集約 |

## ナビゲーション

上部に月送り・今日、日／週／月の切替。月表示内に「手帳／予定名」の切替。カレンダーにカテゴリ凡例を置き、下部に大きな「＋ 予定を追加」。追加はstickyや本文上の重ね表示を使わず、端末内のフレックス配置で独立した高さを確保する。本文と下ペインのスクロール終端は追加領域より上に収まり、全状態でカードを覆わない。モックの外側にある端末・回転・卓上の操作はレビュー専用で製品には含めない。日付選択、表示モード、月内のサンプル予定とフォームは同じDOMで保持し、幅変更で初期化しない。

| 経済指標 | #825A23、淡背景 #F7EEDC |

カテゴリ名と時刻も併記し、色だけで分類しない。土日は文字ラベルも維持。今日の輪郭と選択日の塗りを区別する。

本文は -apple-system / BlinkMacSystemFont / Hiragino Kaku Gothic ProN / sans-serif。日付の大見出しだけ Georgia / Hiragino Mincho ProN / serif、数字は tabular-nums。本文16px、補助12–14px、見出し24–32px、今日56px。8pxを基準に余白、カード16–20px、角丸16–22px。影は薄く、区切りは細線。基本操作対象44px以上（月の密な日セル・行内の帯は例外。選択日の一覧からも編集可能）、キーボードフォーカスを明示。狭い月セルの予定名は省略し、選択日一覧で全文を読める。

## インタラクション注記

- サンプル基準日は2026年11月12日9:41（日本時間）。経済指標の名称・時刻は架空の予定例で実際の公表日程ではない。
- 日セルで選択、予定カードで編集。追加は選択日を初期値にする。月送りと「今日」で閲覧基準日を変更する。
- 保存はモック内の一時メモリだけを更新する。再読込で初期化。削除には別の確認を挟む。キャンセル時は予定に反映しない。フォームが開いたままの開閉・回転で入力を保持する。
- 日／週では月表現切替をhidden属性と `[hidden] { display:none !important; }` で確実に隠す。月へ戻すと選択した表現を復元する。
- 予定名の月行は80px固定。選択日も同じ高さとし、タイトルは省略する。開いた縦626×890で前後月の日を含むグリッドを表示する。複数日帯は行内の最下部22px、1行につき1本。追加の複数日予定は日セルの件数と選択日の一覧で確認する。
- タイトル必須、終了は開始以降。日付をまたぐ予定と終日を表現。月セルは最大2件＋残件数、日セル選択でその日の一覧へ。週をまたぐ帯は各週で継続を示す。
- 編集シートと削除確認は端末枠内の非モーダルdialog（show）として配置。編集中のカレンダー本文はinertにし、レビュー操作バーは常時クリック可能。開閉・回転・幅追従はフォームを再生成しないため入力途中の内容を保持する。シート内をスクロールできる。見出し・ラベル付き、Escと閉じるで終了し、起点にフォーカス復帰。削除確認中は編集シートをinertにし、キャンセルへフォーカスする。
- 日時はnative datetime-localの地域依存表示を避け、`2026/11/12 10:00` 形式のテキスト欄にする。24時間表記・実在日時・終了順序を検証する。日本語の日時ピッカーとキーボードは未実装。
- 製品では保存失敗・容量不足・未保存離脱の通知を設計する。モックには永続化や通知許可の要求はない。

## v1 と後続の境界

v1は日／週／月、2つの月表現、4カテゴリ、追加・変更・削除、幅への追従、ローカル保存。製品化時の保存はIndexedDBを第一候補とし、この成果物では接続しない。クラウド送信、アカウント、同期、サービスワーカー、インストール処理は対象外。Safariの「共有 → ホーム画面に追加」で使う想定の画面設計のみ。

後続の通知、Apple Pencil手書き、iPhone/Googleカレンダー同期、手書き認識、音声・文章入力、タスク表示は、将来の「ツール」領域・設定拡張を置ける余白だけを確保。入力欄や有効そうな未実装ボタンは設けない。

## 前提・未決事項

実機DPR、safe area、折り目と姿勢APIのSafari対応、キーボード時の高さを要検証。ハーフフォールドは手動選択を基本とする。日本語・日本時間・日曜始まりを初期値とし、祝日データ、繰り返し予定、タイムゾーン編集、カテゴリ編集、検索はv1設計の対象外。端末ローカル保存はブラウザデータ削除等で失われ得るため、製品化時には保存状態とバックアップ方針の合意が必要。

## レビュー手順

mockup.htmlを直接開き、十分な幅のブラウザで次を確認する。狭いブラウザでは実幅表示を確認し、基準寸法の確認時はブラウザを広げる。

1. 閉じた縦466×678の初期画面で今日・次の予定・残り2件・追加を確認。閉じた横678×466でも1列で同じ操作が使えること。
2. 閉じた／開いたの縦横で日・週・月を切替。本文を末尾までスクロールし、追加がカードやグリッドを覆わないこと。日・週で手帳／予定名が消え、月で復帰すること。
3. 開いた縦626×890の予定名月で、選択日を変えても行高が変わらず前後月を含む全日が表示されること。月送りで6行月も確認。開いた縦横の週が7列、閉じた縦横の週が縦並びであること。
4. ハーフフォールドの縦横で中央24pxの保護帯、上の月と下の予定を確認。各ペインの末尾までスクロールし、追加操作と重ならないこと。
5. 追加／編集でタイトルと日時を入力したまま、外側の閉じた／開いた／ハーフフォールド／回転／幅に追従を操作。シートの入力が保持され、保存・キャンセル・削除確認・Escが使えること。日時の誤形式・実在しない日付・終了の逆転も確認。

外部通信・永続保存・本番アプリコードは不要。

改訂時の検証：JavaScript構文と日時入力の形式・実在日時チェックを確認。環境のChrome起動制約により、実描画での上記寸法・スクロール・操作確認は未実施。レビュー時に上記手順で確認する。
