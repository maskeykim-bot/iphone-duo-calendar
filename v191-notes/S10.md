# S10（R-70）ノートの日本語変換中に、変換途中の文字が別の行として残る

枝: v19.2（main 5bc8af6 から）。対象: app/js/notes-ui.js。優先度: 高（打った文字が壊れ、そのまま保存される）。
資料: 連携 /workspace/duo-calendar-team/data/連携_調査_ノート変換途中の行_2026-11-20.md、品質 /workspace/duo-calendar-team/qa/bug-v19-1-note-ime-2026-11-20.md と qa/scripts/note-ime-r70.*（仮の直し r70-qa-probe-fix.diff）。コマ design/ref/firstseed-2026-11-20/our-note-bug/note_001〜032.jpg。

## 原因（行番号は 5bc8af6 の notes-ui.js）
- 本文の値を読むだけの getter `readValue()`（L99）が、DOM の形が想定（.nl の中は文字と br だけ＝`sane()` L86）でないと `renderValue(flat())`（L98）で本文を作り直し、**キャレットを戻さない**（本文の頭へ飛ぶ）。変換中かを見ていない。
- iOS WebKit は変換中の文字を `<span>` で包むため `sane()` が false になる。変換の1文字ごとに作り直し→その時点の文字が普通の行として確定し、キャレットが頭へ→次の変換が新しい行として上に積もる（コマと一致）。確定した行はそのまま保存される（sync L302）。
- 変換中もこの道に入る入口は4か所：本文 input（L370→noteChange L202→snap L192→readValue）、selNow（L119）、selectionchange→onSel（L383）、reconcile（L141）。
- `flat()`（L88-96）は本文直下の span（DIV でも BR でもテキストでもない要素）の文字を捨てていた。

## 直し方（品質の仮の直しに沿う。見た目・データ版6・保存の文字の形は不変）
1. `readValue()`：変換中（`composing`）で DOM が想定外なら作り直さず `flat()` を返すだけ。変換中でない作り直しのときは、先に今のキャレット位置（`flatCaret()`）を取り、`renderValue(flat())` のあと `setRange` でその位置へ戻す（頭に飛ばさない）。
2. `flatCaret()` を新設：今のキャレットを文字（記号つき）の通し位置に直す。
3. `selNow()`（L119）：想定外かつ変換中なら作り直さず前の値（`selCache`）を返す。
4. `flat()`：想定外の要素（span など）も `textContent` を拾い、文字を捨てない。
- onSel（L383）と reconcile（L141）は body.value／selectionStart／readValue 経由なので、1〜3 で変換中は作り直さなくなり、一緒に封じられる。
- すでに保存された途中の行は消さない・移さない（連携の方針）。移行なし、IndexedDB/バックアップは版6のまま。
