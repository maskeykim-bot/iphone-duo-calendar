# V193 その2 項目 B・C（ノートの行頭記号・字下げ）

## B. 再現した不具合と原因
素直な打ち込み（空の行で箇条書き／チェック → 英字、Chromium の本物の IME、WebKit）では **記号は消えなかった**。消える（記号が付かない）道を3つ再現した。実機（iPhone の WebKit の変換）でどれが起きているかは box では確かめられない（→ 残った心配）。

| # | 再現の手順 | 起きること | 原因 |
|---|---|---|---|
| 1 | 記号の行で変換を確定 → すぐ Return → 続けて打つ（Chromium の本物の IME・模型の両方で再現） | 次の行が**記号なしのふつうの行**になる | 次の項目を続ける処理（onEnter）が keydown にしか無く、確定の直後 50ms（`compEndAt`）・keyCode 229 では見送る。その Return は beforeinput（plaintext-only では `insertLineBreak`）に落ち、素の改行になる。keydown が来ない／229 で来るキーボードでは毎回こうなる |
| 2 | 空の記号の行を選んだあと、キャレットが行の外（本文の直下。R-70 の note_006 で実機に出た形）にある状態で打つ・変換する（模型） | 文字が**記号なしの別の行**になり、記号は空の行に取り残される | ブラウザが文字を行の div の外に置く。読み取り（flat）は行の外の文字を別の行にする |
| 3 | 空の記号の行で変換し、確定のとき（deleteCompositionText → insertFromComposition）に空になった行の div をブラウザが取り除き、確定の文字を本文の直下／書式のない div に入れ直す（模型） | **記号が完全に消える**（data-pre を持つ div が無くなる） | 記号は行の div の `data-pre` にしか無い。div が作り替えられると失う |

## B. 直し方（js/notes-ui.js）
- **改行**: beforeinput の `insertParagraph`／`insertLineBreak` でも onEnter を通す（Shift+Return だけは keydown で覚えて素の改行のまま）。keydown の道はそのまま（二重には入らない：keydown が処理したら preventDefault 済み）。
- **guard**: 記号の行で入力が始まる直前（beforeinput・compositionstart）に、その行（el・pre・前後の行）を覚える。読み取り `scan()`（旧 flat＋flatCaret を1つに）で、行が空のまま行の外に文字がある → その文字に記号を引き継ぐ／行の div が消えた → 元の前後の行の間の文字に引き継ぐ（文字がまだ無ければ空の記号の行を残す）。覚えるのは入力の間だけ（作り直し・input・compositionend で捨てる）。**変換中は DOM もキャレットも触らない**（R-70 の決まりのまま。作り直し 0 回の試験は通る）。
- **want**: アプリが置いたキャレット（setRange）を覚え、ブラウザがそれを本文の頭（行の外）に戻しても、次の入力はその行へ（変換なしの insertText は自分で行へ入れる。WebKit は beforeinput で動かした選択を使わないため）。指・キーで動かしたら忘れる。
- **文字のある行の記号の付け替え**: 既存の applyFormat がそのまま出来ていた（付ける・替える・外す、字下げは保つ、複数行、キャレットは文字の位置）。コードは変えず、試験で固定した。
- 保存の文字の形は不変。保存済みのごみの行は開いても1文字も変えない（試験あり。guard は入力中の行にしか使わない）。IndexedDB・バックアップは版6のまま。`checkLines` はそのまま（字下げしても同じ一覧が取れる単体あり）。

## C. 字下げの判断
- **保存の形**: 行頭の空白 2 つで1段（`INDENT_UNIT`）、**0〜4 段**（`INDENT_MAX = 4`）。`^\s*- ` で読める今の形。触るのは行頭の空白だけ。半端な空白・タブの行は、その行を動かしたときだけ段にそろう（開いただけでは変えない）。
- **Tab／Shift+Tab**: 選択にかかる箇条書き・チェックの行を1段下げ／上げ（複数行可、記号のない行は動かさない）。選択に記号の行が無ければ preventDefault しない（今の動きのまま）。変換中は何もしない。
- **払い**（PointerEvent・touch だけ）: 動き出し 8 で向きを決め、横＞縦×1.5 のときだけ始める（縦はスクロールに任せる。行に `touch-action: pan-y`）。0.35 秒より長く押してからの動きは文字の選択に任せる。離したとき横 24 以上で1段。指には 1/3 だけ追い（最大 20＝1段）、端（0 段・4 段）は 1/10。離したら 0.18 秒 ease-out で段へ寄せる（視差効果を減らすは寄せなし）。四角（押せる範囲）も一緒に動く。
- **取り合い**: 効くのは本文を編集中（フォーカス中）か、ノートのシートの中だけ。フォーカス中の本文は curl（curlCanStart が false）、シートの中は swipe.js（NB.sheet で止まる）・curl（.dpage の外）が元々始めないので重ならない。ページの上の読むだけの本文は今までどおりめくりが先。フォーカスなしで払ってもフォーカス（キーボード）は出さない。
- **見た目**: 1段 20（文字・点・四角）。見るだけの欄（.dnt・.pvnote）は 1段 16。
- **戻す・やり直す**: applyEdit に乗せた（1回の字下げ＝1つ）。
- 変えなかったもの: 空の項目で Return＝ふつうの行へ（字下げも外す）、行頭で Backspace＝記号を外す。

## 残った心配
1. **実機の再現は出来ていない**。上の 1〜3 は模型と Chromium の IME での再現。iPhone の変換が別の形で行を壊している場合は直っていない可能性がある。実機で「空の行 → 箇条書き／チェック → かなを打って確定 → Return → もう1語」を確かめてほしい。
2. 払いは PointerEvent を合成した試験だけ。実機で、縦スクロールの出だし・文字の選択（長押し）・キャレットを置くタップと取り合わないかは未確認。`touch-action: pan-y` を記号の行に付けた。
3. playwright.config.js の webkit の testMatch から s11i・s11i-design-18-5・s11j が消えているのは別の担当の編集（自分は `v193-note-marks` を足しただけ）。
4. tests/v193-note-marks.spec.js の「見るだけの欄」1本は、閉じた縦の日の欄に `.dnt` が出ることを前提にしている。項目 A で日の欄の作りが変わったら、その1本は出る所に合わせて直す必要がある。
5. sw.js の CACHE・ios sync・全体 Playwright はしていない（まとめ役）。
